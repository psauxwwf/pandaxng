# PandaXNG

Веб-метапоиск через **Lightpanda PandaScript**: DuckDuckGo, Brave и Yahoo.
Без API-ключей, аккаунтов,
платных API, Puppeteer и Playwright. Это самостоятельный проект, не плагин SearXNG.

## Установка и сборка

CLI на Go с **Cobra + Fang**. Без встроенной LLM и конфигурационных
файлов: запрос → Lightpanda → JSON/Markdown. Есть MCP-сервер на `mcp-go`.
JS-парсеры встроены в бинарник через `go:embed`.

Требования:

- Go 1.27+ для сборки; для запуска готового бинарника Go не нужен.
- Lightpanda с командами `run`, `fetch` и PandaScript `Page` (проверено с 1.0.1).
  Установка: <https://lightpanda.io/docs/run-locally/installation/one-liner>.

Сборка: `task build` → `bin/pandaxng` (Linux amd64,
`CGO_ENABLED=0`, статическая сборка). Требуются Task и binutils (`strip`, `objcopy`).

Релиз: `task release` пересобирает бинарник, упаковывает его в
`bin/pandaxng_linux_amd64.tar.gz` и публикует GitHub Release с тегом
`vMM.DD.HH` (например, `v10.19.16`). Нужны `tar` и авторизованный GitHub CLI
(`gh auth login`). Повторная публикация с тем же тегом завершится ошибкой.

Либо сборка напрямую через Go:

```sh
go build -o bin/pandaxng ./cmd/pandaxng
```

## Использование

Три команды без алиасов: `search` для поиска (JSON), `fetch` для чтения страницы
(Markdown), `mcp` для запуска MCP-сервера.

`search` и `fetch` (включая MCP) используют режим ожидания `done`: перед чтением
DOM ждут завершения сетевых запросов и скриптов. Ожидание ограничено `--timeout`
(по умолчанию 20 секунд). Постоянная фоновая активность может привести к таймауту;
ошибки сети и недоступный IPv6 увеличением ожидания не исправляются.

### Поиск: `search`

```sh
./bin/pandaxng search 'linux namespaces'
./bin/pandaxng search 'что такое контейнеры' --engines duckduckgo,yahoo --language ru-RU
./bin/pandaxng search 'lightpanda browser' --engines brave --limit 5 --timeout 25s
./bin/pandaxng search --list-engines
./bin/pandaxng --help
```

По умолчанию: все три движка, максимум 10 результатов с каждого,
три параллельных браузера, 20 секунд на движок, язык `en-US`.

| Флаг | Назначение |
|---|---|
| `--engines` | Движки через запятую: `duckduckgo,brave,yahoo` |
| `--limit` | Результатов на движок, 1–50 (по умолчанию 10) |
| `--jobs` | Параллельных браузеров, 1–3 (по умолчанию 3) |
| `--timeout` | Таймаут на движок: Go duration (`20s`, `1m`), диапазон 1s–2m |
| `--language` | Язык браузера (по умолчанию `en-US`) |
| `--lightpanda` | Путь к исполняемому файлу (по умолчанию `lightpanda` из PATH) |
| `--list-engines` | Вывести поддерживаемые движки без поиска |

Вывод — JSON:

- `query`: исходный запрос;
- `results`: объединённые результаты `{url, title, content, engines}`;
- `engines`: исходные результаты и состояние каждого движка;
- состояния: `ok`, `empty`, `blocked`, `parse_error`, `timeout`, `error`.

Результаты чередуются между движками, одинаковые URL объединяются с указанием
источников. Если хотя бы один движок вернул `ok` или `empty`, код завершения — `0`;
иначе — `1`. Ошибки аргументов также завершаются кодом `1`.
Частичные ошибки остаются в `engines`. `empty` — распознанная страница без
результатов, а не любая страница, на которой не сработал парсер.
`Ctrl+C` отменяет запущенные процессы.

### Чтение страницы: `fetch`

```sh
./bin/pandaxng fetch 'https://ident.me'
./bin/pandaxng fetch 'https://example.com' --timeout 30s --language ru-RU
./bin/pandaxng fetch 'https://example.com/article' > article.md
```

Запускает `lightpanda fetch --dump markdown --log-format pretty --log-level info`
с теми же User-Agent и TLS-флагом, что и поиск. Страница загружается с выполнением
JavaScript, выводится Markdown целиком (без JSON). Логи Lightpanda не смешиваются
с содержимым; при сбое диагностика выводится в stderr, код завершения — `1`.
HTTP 4xx/5xx считаются ошибками. Поддерживаются `--timeout`, `--language`,
`--lightpanda`; `Ctrl+C` останавливает процесс.

CLI-команда `fetch` и MCP-инструмент `fetch_content` используют одну реализацию.
Пока без кэша и пагинации.
Разрешены только HTTP(S) URL без логина/пароля, но доступ во внутреннюю сеть
в локальной CLI-команде не блокируется: передавайте доверенные URL.
В режиме MCP доступ тоже разрешён по умолчанию; для блокировки используйте
`--disable-private-urls`. Проверка имени хоста TLS отключена
(см. раздел «Как работает»).

### MCP-сервер: `mcp`

Используется [`mark3labs/mcp-go`](https://github.com/mark3labs/mcp-go).

```sh
# stdio — по умолчанию; stdout содержит только JSON-RPC
./bin/pandaxng mcp
./bin/pandaxng mcp --transport stdio

# Streamable HTTP, endpoint http://127.0.0.1:8080/mcp
./bin/pandaxng mcp --transport http
./bin/pandaxng mcp --transport http --listen 127.0.0.1:9090 --timeout 30s
```

Оба транспорта предоставляют одинаковые инструменты:

| Tool | Параметры | Результат |
|---|---|---|
| `search` | `query` (обязательно), `max_results` (1–50, по умолчанию 10 на движок), `engines` (массив, по умолчанию все три), `language` | JSON с объединённой выдачей и статусами движков; также в `structuredContent` |
| `fetch_content` | `url` (обязательно), `language` | Markdown страницы после выполнения JavaScript |

Серверные флаги `--lightpanda`, `--timeout`, `--language` задают общие настройки.
Ошибки инструментов возвращаются как MCP `isError`; при частичном успехе поиска
ошибки остальных движков остаются в отчёте. Одновременно исполняются максимум
3 tool-вызова, каждый поиск запускает до 3 браузеров. Ожидание слота тоже
ограничено таймаутом. `Ctrl+C` останавливает сервер и браузеры; закрытие stdin
завершает stdio-сервер.

Пример настройки stdio в MCP-клиенте (замените путь на абсолютный):

```json
{
  "mcpServers": {
    "pandaxng": {
      "command": "/path/to/pandaxng/bin/pandaxng",
      "args": ["mcp"]
    }
  }
}
```

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "PANDAXNG": {
        "type": "local",
        "command": ["pandaxng", "mcp"],
      },
    },
  },
}
```

**Безопасность:** MCP по умолчанию разрешает сетевые обращения к внутренним
адресам — используйте только с доверенными клиентами (есть риск SSRF).
Для блокировки запустите `mcp --disable-private-urls`: Lightpanda получит
`--block-private-networks`, который действует также на перенаправления и ресурсы
страницы. HTTP слушает localhost, проверяет
Host средствами SDK и отклоняет чужой Origin. Встроенных аутентификации и TLS
для входящего HTTP нет: не публикуйте порт в интернет без защищённого reverse
proxy. Если прокси обращается через loopback, передавайте upstream Host localhost.
TLS-флаг исходящих запросов остаётся небезопасным, как и в CLI.

## Как работает

Go-бинарник собирает запрос и передаёт встроенный JS-скрипт в
`lightpanda run -` через stdin. `scripts/common.js` открывает страницу через
`Page.goto()`, выполняет DOM-парсер через `Page.evaluate()` и возвращает объект.
У каждого движка собственные селекторы в `scripts/engines/`. Результаты
извлекаются из публичной веб-страницы, а не из закрытых API. Для изменения
разметки поисковика достаточно поправить его JS-файл.
После изменения встроенных скриптов бинарник нужно пересобрать.

Структура:

- `cmd/pandaxng/` — команды `search`, `fetch`, `mcp` и оформление Fang;
- `internal/pandaxng/` — запуск Lightpanda, проверка URL и объединение выдачи;
- `internal/mcpserver/` — MCP tools и транспорты stdio/HTTP;
- `scripts/embed.go` — встраивание JS-парсеров;
- `scripts/common.js`, `scripts/engines/` — общая логика поиска и парсеры движков.

Каждый запуск обязательно использует:

```text
--user-agent "AppleWebKit/537.36 (X11; Linux x86_64) (KHTML, like Gecko) Chrome/152.0.0.0 Safari/537.36"
--insecure-disable-tls-host-verification
```

**Внимание:** второй флаг отключает проверку имени хоста TLS-сертификата.
Он включён по требованию пользователя и снижает безопасность соединений.

## Ограничения

- Реализована первая страница обычного веб-поиска. Картинки, новости, видео
  и пагинация не входят в этот проект.
- Ни один публичный поисковик не гарантирует доступ без CAPTCHA с любого IP.
  Lightpanda не гарантирует обход антибот-защиты.
- CAPTCHA не решается автоматически; повторов нет.
  Аккаунты и пользовательские токены не используются. Сайты могут выставлять
  обычные временные cookies в рамках одного браузерного процесса.
- Разметка сайтов меняется; `parse_error` явно сообщает о несовпадении
  селекторов, неполной странице или неизвестной блокировке.
- Сессии между запросами не сохраняются. Запросы идут напрямую, без настройки прокси.
- `--language` задаёт язык браузера/Accept-Language, но не гарантирует регион выдачи.

## Тесты

```sh
go test -race ./...
go vet ./...
```

Тесты проверяют CLI, URL, запуск процессов, обработку ошибок, агрегацию,
MCP по stdio и HTTP без запросов к внешним поисковикам.
При наличии Lightpanda интеграционные тесты поднимают локальный HTTP-сервер
и проверяют чтение страницы с выполнением JavaScript, обработку HTTP-ошибок
и блокировку внутренних сетевых адресов. Без Lightpanda эта группа пропускается.
Для реального сетевого smoke-теста используйте команду запуска выше и смотрите
`engines[].status`, а не только общий exit code.
